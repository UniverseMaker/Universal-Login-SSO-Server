# `tools/` — 릴리스 도구

**이 폴더는 배포물이 아니다. 서버에 올리지 마라.**

두 층을 구분하면 헷갈리지 않는다.

| 층 | 무엇이 들어가는가 |
|---|---|
| **저장소** (이 git 저장소) | 소스 + 문서 + **릴리스 도구(`tools/`)** |
| **서버** (호스팅에 업로드하는 것) | `server/` · `public/` · `examples/` **뿐이다** |

여기 있는 스크립트는 **새 버전을 내보내는 사람이 자기 PC에서 CLI로** 돌린다.
설치·동작에는 전혀 쓰이지 않는다. 저장소를 clone해 **설치만** 할 사람은 이 폴더를 무시해도 된다.

> **올리면 무슨 일이 생기나 —** 두 스크립트 모두 CLI 전용 `$argv`를 읽으므로 브라우저로 열면
> 그 자리에서 죽는다. 기능이 오작동하지는 않는다. 문제는 `display_errors`가 켜진 호스팅
> (공용 호스팅의 흔한 기본값)에서 **그 오류가 서버의 절대 경로를 화면에 그대로 인쇄한다**는 것이다.
> 같은 폴더의 `.htaccess`가 그 경우를 막지만, 그것은 두 번째 방어선이고
> `.htaccess`가 무시되는 환경(nginx · `AllowOverride None`)에서는 그마저 없다.
> **첫 번째 방어선은 폴더를 아예 업로드 대상에서 빼는 것이다.**
> 제외 목록은 `INSTALL.md` 1-1절과 8-2절 두 곳에 있다.

**요구사항:** PHP CLI 하나뿐이다. Composer도, 확장 모듈도, 네트워크도 쓰지 않는다.
어느 쪽도 **파일을 읽고 쓰는 것 외의 부작용이 없다** — DB에 접속하지 않고, 아무것도 전송하지 않는다.

## `bump_asset_version.php` — 자산 URL의 `?v=` 일괄 치환

브라우저 캐시 무효화의 **주 수단**은 자산 URL에 붙은 버전 쿼리다
(`href="assets/style.css?v=1.3.0"`). 이 값이 바뀌지 않으면 새 버전을 올려도 브라우저가 옛
CSS·JS를 계속 쓴다. 자산에는 `immutable, max-age=31536000`이 걸려 있어 **서버 쪽 철회 수단이 없다.**

**손으로 고치지 마라.** 참조가 여러 파일에 흩어져 있어 반드시 일부가 빠진다.
이 스크립트가 만들어진 이유가 정확히 그것이다(리더 판정 D-84).

### 쓰는 법

```bash
# 저장소 루트에서. tools/ 의 부모가 곧 설치 루트다.
php tools/bump_asset_version.php 1.4.0 --dry-run
php tools/bump_asset_version.php 1.4.0 --version-txt=1.4.0_20260915
```

**항상 `--dry-run`을 먼저 돌려라.** 판정과 종료코드는 `--dry-run`에서도 같다 — 다른 것은
파일을 쓰지 않는다는 점뿐이다.

### 옵션

| 옵션 | 의미 |
|---|---|
| `--dir=<경로>` | 대상 설치 루트 = `public/`을 가진 폴더. **생략하면 이 스크립트의 상위 폴더**를 쓴다. 상위에 `public/`이 없으면 상위를 작업 루트로 보고 그 안의 가장 최근 `v{x}.{y}.{z}_{YYYYMMDD}` 폴더를 고른다 |
| `--from=<현재버전>` | 치환 대상을 이 값으로 한정한다. 생략하면 파일에서 발견된 모든 `?v=` 값이 대상이다 |
| `--version-txt=<문자열>` | `public/version.txt`를 이 내용으로 덮어쓴다. **형식이 `{버전}_{YYYYMMDD}`로 달라 자동 추론하지 않는다** |
| `--dry-run` | 파일을 쓰지 않고 결과만 출력한다 |

### 종료코드 — 4가지 경로

**`$?`만 보고 다음 단계로 넘어가도 되게 만들어 두었다.** 각 코드는 **해야 할 조치가 서로 다르다.**

| 코드 | 무슨 일인가 | 무엇을 고쳐야 하나 |
|---|---|---|
| `0` | 정상. 갱신되지 않은 버전 표기가 없다 | — |
| `1` | **산출물에 결함이 있다.** (a) 자산 참조에 `?v=`가 없다 (b) 화면 푸터에 버전 문자열이 손으로 박혀 있다 | **파일.** 출력이 파일·문자열을 지목한다. 고친 뒤 다시 실행하라 |
| `2` | 사용법 오류, 또는 파일을 읽거나 쓸 수 없다 | **환경·인자.** 경로와 권한을 확인하라 |
| `3` | **치환할 자리를 하나도 갱신하지 못했다.** `--from` 값이 파일의 현재 값과 달라 전부 건너뛰었다 | **명령.** 산출물은 깨지지 않았다. `--from` 값을 고치거나 `--from`을 빼라 |

`1`과 `3`이 동시에 성립하면 **`1`이 나간다** — 산출물 결함이 더 급하다. `1`을 닫고 다시 실행하면
남아 있던 `3`이 드러난다.

> **`1`과 `3`을 합치지 않은 이유.** `1`의 조치는 "지목된 파일을 고쳐라"이고 `3`의 조치는
> "명령을 고쳐라"다. `--from` 오타에 `1`을 재사용하면 **운영자가 없는 결함을 파일에서 찾게 된다.**
>
> `3`은 나중에 추가됐다. 그전에는 `--from` 오타로 아무것도 치환되지 않아도 종료코드가 `0`이라,
> `$?`만 확인하는 절차가 **조용히 통과했다.** 실패했을 때 "다음 할 일:" 안내를 인쇄하지 않는 것도
> 같은 이유로 함께 막았다 — 사람이 읽는 출력과 종료코드가 어긋나면 안 된다.

### 이 스크립트가 **고치지 않는** 것

- **`public/assets/ulogin-client.js`의 `UloginClient.version`** — 연동 클라이언트의 **공개 API
  버전**이고 자산 URL의 `?v=`와 완전히 별개다(리더 판정 D-72). 스크립트는 `*.html`만 연다
- **`public/version.txt`** — 형식이 `{버전}_{YYYYMMDD}`로 달라 자동 추론하지 않는다.
  `--version-txt=`로 명시할 때만 쓴다. 안 주면 갱신하라고 알려 준다
- **`server/**` · 문서(`README.md`·`INSTALL.md`·`CHANGELOG.md` 등)** — 대상이 아니다
- **HTML 주석 안의 버전 문자열** — 의도적이다. 주석에는 "v1.2.0에서 이렇게 했다" 같은
  **과거 릴리스를 가리키는 정당한 서술**이 있고, 일괄 치환하면 스크립트가 그 기록을 위조한다
- **`?v=`가 없는 참조에 값을 붙여 주는 것** — 조용히 붙여 주면 왜 빠져 있었는지가 묻히고
  다음 릴리스에서 반복된다. 지목해 보고하고 **종료코드 1로 실패한다**

### 갱신 후 확인까지가 절차다

출력의 **`버전없음` 열이 0인지 확인하라.** 0이 아니면 그 자산은 버전 쿼리 없이 남아 있고,
그 파일은 새 버전을 올려도 브라우저가 옛 것을 계속 쓴다.
업로드 뒤 `{설치루트}/public/version.txt` 값과 개발자도구 Network 탭의 `?v=` 값을 함께 본다.
전체 절차는 `INSTALL.md`의 `## 8. 새 버전으로 갱신하기`에 있다.

## `php72_scan.php` — PHP 7.2 호환성 정적 스캐너

**이 프로젝트의 최소 요구 버전은 PHP 7.2다.** 공용 호스팅에는 아직 7.2가 흔하다.

**`php -l`로는 이 검사를 할 수 없다.** 최신 PHP로 돌리는 `php -l`은 7.3·7.4·8.0 전용 문법도
전부 통과시킨다. "문법 오류 없음"이 "7.2에서 돈다"를 뜻하지 않는다.

그래서 `token_get_all()` 기반 자체 스캐너를 만들었다(리더 판정 D-58). 토크나이저가 필수인
대표 사례가 **함수 호출의 trailing comma**(7.3+)다 — 배열 리터럴의 trailing comma와
`grep`으로 구분할 수 없다.

### 쓰는 법

```bash
# 저장소 루트에서 — 서버 코드와 이 폴더의 도구를 함께 검사한다
php tools/php72_scan.php server tools

php tools/php72_scan.php server --notes-are-errors   # NOTE 도 종료코드에 반영
php tools/php72_scan.php server --list-funcs         # 호출하는 전역 함수 전체 덤프
php tools/php72_scan.php . --exclude=public/assets   # 경로 조각으로 제외
```

인자로 파일과 디렉토리를 모두 받는다. 디렉토리는 재귀하며 `.php`만 본다
(`vendor/`·`node_modules/`는 자동 제외).

### 출력과 종료코드

`ERROR`(7.2에서 확실히 깨진다)와 `NOTE`(사람이 봐야 한다)를 나눠 인쇄하고 규칙별 집계를 낸다.

| 코드 | 의미 |
|---|---|
| `0` | `ERROR` 0건 (`--notes-are-errors`를 줬다면 `NOTE`도 0건) |
| `1` | 검출 있음 |
| `2` | 사용법 오류 / 대상을 찾을 수 없음 |

**회귀 게이트로 쓸 수 있다** — `server/`에 대해 `ERROR 0`이 이 프로젝트의 기준선이다.

### 두 가지 함정

1. **스캐너는 PHP 8.x로 실행해야 한다.** 스캐너 자신은 7.2 문법으로 작성했지만, 8.0+ 문법을
   *검출*하려면 그 문법을 파싱할 수 있는 런타임이 필요하다. 7.2의 `token_get_all()`은
   8.0 문법 파일에서 파싱에 실패한다
2. **"검출 0건"이 스캐너가 침묵하고 있다는 뜻일 수 있다.** 실제로 이 스캐너에서 규칙이
   영구히 발화하지 않는 버그가 잡힌 적이 있다. **양성 픽스처(일부러 위반을 심은 파일)와
   음성 픽스처(7.2에서 합법인 코드만 담은 통제군)를 한 쌍으로 돌려** 스캐너가 살아 있는지
   먼저 확인하라. 검사기를 검증하지 않은 "0건"은 증거가 아니다

### 검출 억제

의도적인 상위 버전 경로에는 같은 줄 또는 바로 윗줄에 주석을 단다.

```php
if (PHP_VERSION_ID >= 70300) {
    // php72-scan: ignore ARG_ARRAY_FORM
    setcookie($name, $value, $options);
}
```

**버전 분기로 감싼 경로에만 쓰라.** 억제는 검출을 지우는 것이지 호환을 만들어 주지 않는다.

## 알아 둘 것

**`glob()`을 쓰지 않는다.** `glob()`은 패턴의 `[...]`를 문자 클래스로 해석하므로, 경로에
대괄호가 들어간 위치(예: `.../[archive] my-project/...`)에서 **오류 없이 0건을 반환한다.**
조용히 실패하는 종류라 "0건"을 "대상이 없다"로 오독하게 된다.
`bump_asset_version.php`는 `scandir()` + 확장자 검사를 쓴다. 이 폴더에 도구를 추가한다면 같게 하라.

**두 도구 모두 릴리스 절차의 일부다.** 새 버전을 내보내는 순서는 대략 이렇다.

1. `php tools/php72_scan.php server tools` → `ERROR 0` 확인
2. `php tools/bump_asset_version.php <새버전> --dry-run` → `버전없음` 열이 0인지 확인
3. `php tools/bump_asset_version.php <새버전> --version-txt=<새버전>_<YYYYMMDD>` → 종료코드 0 확인
4. `server/` · `public/` · `examples/` 업로드 (**`tools/`는 올리지 않는다**)
5. `INSTALL.md` `## 8. 새 버전으로 갱신하기`의 나머지 확인 단계
