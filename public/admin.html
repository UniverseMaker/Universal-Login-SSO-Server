게이트 점검

무엇을 찾는가 이름이 민감해 보이는데(키 · 시크릿 · 토큰 · 비밀번호 · 자격증명) 최소 등급 게이트가 하나도 걸려 있지 않은 시크릿을 모든 서비스에서 찾습니다. 게이트가 없으면 그 서비스에 가입한 모든 사용자가 이 값을 받아 갑니다.
각 축의 기본값 이하로 건 게이트는 게이트로 세지 않습니다 — 계정등급 basic(과 그 아래 guest) · 결제등급 free · 역할 user 입니다. 전원이 이미 그 값을 갖고 있어 통과 조건이 “제한 없음”과 같기 때문입니다 (basic 은 신규 가입자에게 박히는 값입니다).
이 표의 판정은 브라우저가 서버 규칙을 사본으로 다시 적용한 결과입니다. 실제 차단은 생성·수정 시점에 서버가 합니다 — 서버에 조회용 판정 엔드포인트가 없어 이 화면이 직접 계산합니다. 사본이 서버와 어긋나면 이 표가 틀립니다. 서버와 다르게 보이면 서버가 정답입니다.
이 점검이 보지 않는 것 — 시크릿 한 건의 최소 등급만 봅니다. 서비스의 default_account_level 이 그 게이트를 가입 시점에 자동으로 열어 주는 조합(예: 최소 계정등급 vip + 같은 서비스의 기본 계정등급 vip)은 여기서 잡히지 않습니다. 게이트가 걸린 것처럼 보이지만 그 서비스 가입자 전원이 통과합니다. 설정 번들 import 경로만 그 조합을 거절합니다 — 이 콘솔의 “수정”으로 만든 조합은 거절되지 않습니다. 서비스 탭에서 기본 계정등급을 함께 확인하세요.
이 화면은 아무것도 바꾸지 않습니다. 목록을 보고 사람이 판단해 “수정”으로 게이트를 거세요. 운영 중인 서비스의 등급을 일괄로 올리면 정상 연동 앱이 갑자기 막힙니다.
의도적으로 공개한 값도 여기 나옵니다 — 다만 따로 묶어 보여 줍니다. 생성·수정 시 allow_public=true 로 확인하고 통과시킨 행은 목록 응답의 allow_public 표식으로 구분되므로, 결과가 “확인이 필요한 행”과 “공개를 승인한 행” 두 묶음으로 나뉩니다. 위쪽 묶음을 먼저 보세요.
위쪽 묶음을 해소하는 방법은 “수정”에서 최소 등급 게이트를 거는 것입니다. 이 콘솔에는 allow_public 을 켜는 입력이 없습니다 — 공개 승인은 allow_public=true 를 실어 보내는 API 직접 호출로만 됩니다(의도된 제약입니다). 게이트 없이 공개하는 것이 정말 맞다고 판단했을 때만 그 경로를 쓰세요.
업그레이드 중인 설치본에서는 표식이 전부 false 로 옵니다 — 마이그레이션 0002 가 아직 적용되지 않은 상태입니다. 이 콘솔에는 스키마 적용 상태를 보여 주는 화면이 없습니다. server/migrate.php 의 상태 화면에서 확인하세요(설치 안내서 8-2절). 적용 전까지는 승인 여부를 로그 → 관리자 조작 로그의 secret.create · secret.update 기록으로 봐야 합니다.

로그

한 줄 = 한 번의 접근이 아닙니다 이 표의 한 줄은 (세션 × 출처 × 1시간) 묶음 하나입니다. 같은 세션이 같은 시간대에 같은 경로로 몇 번을 받아 가든 줄은 하나이고, 실제 전달 횟수는 전달 횟수(hits) 칸에 누적됩니다. 아래 페이지 표시의 “전체 N건”도 줄(버킷) 수이지 접근 횟수가 아닙니다.
값(키 내용)은 저장되지 않습니다 — 키 이름만 남습니다. 시크릿이 실제로 나가지 않은 요청(빈 payload)은 아예 기록되지 않으므로, 줄이 없다는 것은 “호출이 없었다”가 아니라 “시크릿이 나가지 않았다”는 뜻입니다.
최초 IP 와 최근 IP 가 다른 줄은 같은 세션이 여러 IP 에서 쓰였다는 뜻입니다 — 토큰 탈취의 신호일 수 있으니 먼저 보세요.
