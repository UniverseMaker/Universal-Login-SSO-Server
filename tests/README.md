# `tests/` — 회귀 안전망

**이 폴더는 배포물이 아니다. 서버에 올리지 마라.** `tools/` 와 같은 층이다.

| 층 | 무엇이 들어가는가 |
|---|---|
| **저장소** (이 git 저장소) | 소스 + 문서 + 릴리스 도구(`tools/`) + **회귀 테스트(`tests/`)** |
| **서버** (호스팅에 업로드하는 것) | `server/` · `public/` · `examples/` **뿐이다** |

업로드 제외 목록은 `INSTALL.md` **1-1절**과 **8-2절** 두 곳에 있고, 그 둘은 같은 내용이어야 한다.
저장소를 clone해 **설치만** 할 사람은 이 폴더를 통째로 무시해도 된다.

> **올리면 무슨 일이 생기나 —** `tools/` 와 같다. 여기 있는 PHP는 전부 CLI 전용이라
> 브라우저로 열면 그 자리에서 죽는데, `display_errors`가 켜진 호스팅(공용 호스팅의 흔한
> 기본값)에서는 **그 오류가 서버의 절대 경로를 화면에 그대로 인쇄한다.**
> 게다가 이 폴더에는 `fixtures/` 가 있고 그 안에는 **일부러 깨뜨려 둔 미니 설치 루트**가
> 들어 있다 — 결함 있는 `.htaccess` 사본과 결함 있는 화면 사본이다. 그것이 공개 URL에
> 올라가 있어야 할 이유는 하나도 없다.
> **첫 번째 방어선은 폴더를 아예 업로드 대상에서 빼는 것이다.**

## 한눈에

| | |
|---|---|
| **케이스** | **99** — 자기검증 39 별도. 티어 1 **22** · 티어 2 **53** · 티어 3 **24** |
| **소요** | **약 18~21초** (아래 「소요 시간」 참조. 티어 3이 시간의 대부분이고 DB 속도에 좌우된다) |
| **의존성** | **0.** PHP CLI 하나뿐이다. Composer 없음 · PHPUnit 없음 · 빌드 없음 · 네트워크 없음 |
| **예외 하나** | 티어 3만 **실 MySQL/MariaDB** 와 `pdo_mysql` 을 쓴다. **없으면 SKIP** 된다 |
| **저장소에 남기는 것** | **없다.** 테스트 DB도 샌드박스 웹루트도 `php -S` 프로세스도 종료 시 되돌린다 |

```bash
php tests/run.php            # 전부
php tests/run.php --tier=1,2 # DB 없이 돌아가는 것만 (75 케이스, 약 7초)
```

> ### DB 없이 돌린 `exit 0` 을 「전부 통과」로 읽지 마라
>
> 종료코드 `3`(**한 건도 안 돌았다**)은 말 그대로 **한 건도** 안 돌았을 때만 난다.
> `php tests/run.php` 를 DB 없이 돌리면 티어 1·2 의 75 케이스가 통과하므로
> **티어 3 의 24 케이스가 전부 SKIP 이어도 종료코드는 `0` 이다.** 설계대로다 —
> 그 실행에 고칠 코드는 없다. 하지만 **그 `0` 은 「티어 3 이 덮는 것까지 통과했다」는
> 뜻이 아니다.** 종료코드 `3` 은 `--tier=3` 만 지정해 돌렸을 때 난다.
>
> DB 없는 실행에서 **실제로 검증되지 않는 것**(실측: `skip 24`):
>
> | SKIP 되는 것 | 그 실행에서 **아무 근거도 없는** 단언 |
> |---|---|
> | `t_10_schema` (4) | `schema.sql` 이 실 MySQL 에 **무수정으로 적용된다** · 전 테이블 InnoDB/utf8mb4 · `SUM(col = ?)` 관용구가 동작한다 · `login_logs.result` 폭이 충분하다 |
> | `t_20_migration_paths` (3) | **신규 설치와 업그레이드가 같은 스키마에 도달한다**(D-175) · `migrate.php verify`·`status` 가 동작한다 |
> | `t_30_cookie_branches` (3) | 두 `send_cookie()` 분기가 **바이트 동등**하다 · 실 세션 쿠키에 `HttpOnly`·`SameSite` 가 붙는다 |
> | `t_40_blast_radius` (4) | `api/**` 전 엔드포인트가 익명 GET/POST 에 **표준 봉투**로 답한다 · 문서화되지 않은 5xx 가 없다 · 보호된 엔드포인트가 `AUTH_REQUIRED` 를 낸다 |
> | `t_50_regression_walk` (6) | register → login → me → 비밀번호 변경 → logout → **401** 이 실제로 흐른다 · `session_id` 가 쿠키 값으로 통하지 않는다(D-29) |
> | `t_60_concurrency` (4) | 락아웃·레이트리밋이 **실제로 막는다** · 멱등키가 동시 요청에서 **이중 차감을 막고**, 과하게 막지도 않는다 |
>
> **자기검증의 분모도 같이 줄어든다.** `s_40_live_oracle.php` 의 픽스처 7개(양성 5 ·
> 음성 2)가 DB 를 쓰므로 자기검증이 **39 → 32** 로 줄고, 그러면 **스키마 비교기 자신이
> 그 실행에서 검증되지 않는다.** 이것이 조용히 사라지지 않도록 요약 줄이
> `7 fixture(s) SKIPPED (not self-verified)` 를 찍고 그 7건의 이름을 나열한다.
>
> **배포 게이트로 쓸 때는 티어 3 을 돌린 실행이어야 한다.** DB 없는 실행은
> 「정적·단위 회귀가 깨지지 않았다」까지만 말한다.

## 왜 있는가

**이 팀은 테스트를 안 쓰는 팀이 아니라 쓰고 버리는 팀이었다.**

`_workspace/` 의 리포트 90여 건 중 20건 이상이 자기 라운드에서 만든 일회용 검증
하네스를 언급한다. 쿠키 헤더 **71 케이스 SAME / DIFF 0**, `api/**` 32파일 ×
**64 요청** 폭발반경 — 전부 실제로 돌았고 숫자까지 보고됐는데 **그 코드가 저장소에
없었다.** 다음 버전이 같은 자리를 건드리면 처음부터 다시 만들거나, 만들지 않고 넘어갔다.

v1.4.0 한 라운드에서 나온 결함 넷이 그 대가다. **넷 다 테스트로 잡히는 종류다.**

| 결함 | 여기 있는 어느 테스트가 잡는가 |
|---|---|
| 「하루 24행」 전제로 설계했는데 실제는 요청과 1:1 | 티어 3 — 행 수 단언 |
| 429 수정이 **신호 소실 17~18/20** 을 만듦 | 티어 3 `t_60_concurrency` |
| 백엔드가 만든 필드를 화면이 안 읽고 **「서버가 안 준다」는 거짓 문구**를 띄움 | 티어 1 `t_50_wiring` |
| 계약서가 코드와 **반대**를 말하고 그것이 코드 주석으로 역전파 | 티어 1 `t_20_boundaries` · `t_30_identifiers` |

## 쓰는 법

```bash
# 저장소 루트에서. 전부 (자기검증 -> 티어 1 -> 2 -> 3)
php tests/run.php

php tests/run.php --tier=1               # 정적만. DB·서버 불필요
php tests/run.php --tier=1,2 --verbose
php tests/run.php --filter=cookie        # 이름·파일명으로 걸러 돌린다
php tests/run.php --list                 # 무엇이 돌지 목록만
php tests/run.php --notes-are-errors     # NOTE 도 종료코드에 반영
php tests/run.php --no-selfcheck         # 0단계를 끈다 (CI 에서는 쓰지 마라)
```

> **`-n` 없이 돌려라.** 이 프로젝트는 `mbstring` · `openssl` 을 쓴다. `php -n` 으로
> 돌리면 그 케이스들이 **SKIP** 되고(실패가 아니다), 스위트가 실제로 덮는 범위가 조용히 줄어든다.
> 확장 부재는 산출물 결함이 아니라 환경 문제라서 실패가 아니라 SKIP 으로 만들었다.

> **스캐너 위임 때문에 PHP 8.x 로 돌려야 한다.** `tools/php72_scan.php` 는 8.0+ 문법을
> *검출*하기 위해 그 문법을 파싱할 수 있는 런타임이 필요하다. 7.2 로 돌리면 스캐너 자신이 죽는다.
> **대상 코드의 최소 요구 버전이 7.2 인 것과 러너를 돌리는 PHP 버전은 별개다.**

### 티어 3 접속 정보

환경변수가 1순위, `tests/config.local.php`(gitignore 대상)가 2순위다.

```bash
ULOGIN_TEST_DB_HOST=127.0.0.1 ULOGIN_TEST_DB_PORT=3306 \
ULOGIN_TEST_DB_USER=root ULOGIN_TEST_DB_PASS= \
ULOGIN_TEST_DB_NAME=ulogin_test ULOGIN_TEST_HTTP_PORT=8199 \
php tests/run.php --tier=3
```

자세한 것은 `tests/config.sample.php`. 없으면 티어 3 이 **전부 SKIP** 된다.

> **DB 이름은 `ulogin_test` 로 시작해야 한다.** 러너는 그 접두를 갖지 않은 이름의 DB를
> **만들지도 지우지도 않는다.** 운영 DB를 가리키는 값을 실수로 넣어도 그 DB는 건드려지지 않는다.
> 접두 가드가 이 스위트의 유일한 파괴 방지 장치이므로 **가드를 우회하도록 고치지 마라.**
> 개발 PC의 살아 있는 인스턴스와 완전히 떼어 놓고 싶으면 임시 인스턴스를 다른 포트에
> 띄우고 `ULOGIN_TEST_DB_PORT` 로 가리켜라 — 이 라운드의 실측이 그 방식이었다.

| 단계 | 케이스 | 시간 |

## 티어 구성 — 각각 무엇을 잡고 **무엇을 못 잡는가**

### 티어 1 — 정적 (`tier1_static/`) · DB·서버 불필요 · 약 7초 · 22 케이스

QA 가 매 라운드 손으로 하던 교차 대조를 코드로 옮긴 것이다. 새 검증을 발명한 게
아니라 **이미 하던 일을 저장**한다.

| 검사 | 잡는 것 |
|---|---|
| `php -l` 전 파일 | 구문 오류 |
| `tools/php72_scan.php` 위임 | 7.3+ 문법 혼입 |
| `tools/bump_asset_version.php --dry-run` 위임 | 자산 `?v=` 누락 (D-84) |
| 엔드포인트 ↔ 프론트 호출 양방향 | 없는 URL 호출 · 죽은 API |
| 에러 코드 3자 대조 | 폴백 문구 없는 코드 · 죽은 분기 |
| 화면 링크 대상 실재 | 404 링크 |
| 팬텀 식별자 | 주석이 없는 함수를 인용 (D-148) |
| 주석의 줄 번호 인용 | 낡은 위치 안내 (D-92 · NOTE 급) |
| `login_logs.result` 값 4자 대조 | 값 집합 드리프트 |
| 마이그레이션 DDL 가드 | 가드 없는 DDL (러너가 파일을 거부한다) |
| `.htaccess` 규칙 존재 | 규칙 소실 |
| 생산자 ↔ 소비자 배선 | 소비자 없는 필드 · 없는 필드를 읽는 화면 (D-172) |
| 테이블 상수 3자 한 벌 | 업그레이드 직후 전 엔드포인트 사망 (D-151) |
| 불투명 `json_out($var)` 의 키 못박기 | 배선 검사가 **볼 수 없는 자리에서** shape 이 조용히 바뀌는 것 (D-172 구멍) |

**못 잡는 것**
- **런타임에 만들어지는 것.** `ui.js` 의 `tabs()` 가 설정하는 ARIA 역할처럼 JS 가
  DOM 에 붙이는 속성은 정적으로 보이지 않는다. 이 조사에서 실제로 겪은 함정이고,
  **없는 결함을 지어내는** 방향이라 더 나쁘다. 그래서 런타임 설정 속성은 판정하지 않는다
- **`json_out($변수)`** 처럼 응답을 조립해 넘기는 호출부. 정적으로 shape 을 알 수 없다.
  **현재 1건**(`api/admin/user_points.php`)이고 예산으로 크기를 재서 늘면 실패시킨다.
  **크기만 재는 것으로는 부족하다** — 크기가 그대로여도 그 안의 shape 이 바뀌면 배선
  검사는 계속 조용하다. 그래서 그 한 곳의 키 8개를 **손으로 못박고** 대조한다:
  바뀌면 실패하고, 그때 할 일은 목록 갱신이 아니라 **새 키의 소비자 배정**이다(D-172).
  키 8개 각각의 소비자 유무도 그 케이스가 직접 본다 — 위의 양방향 diff 가 이 파일을
  건너뛰므로 거기가 그 8개에 대한 **유일한** 소비자 검사다.
  오늘 그 8개가 통과하는 이유는 **우연히 전부 다른 엔드포인트에서도 생산되기 때문**이고
  (`log_id`·`admin_log_id` 는 사유와 함께 면제 등재), 이 파일에만 있는 키가 새로 생기면
  그 우연이 깨진다. 못박기가 막는 것이 정확히 그 순간이다.
  **못박기가 증명하지 않는 것:** shape 이 *옳다*는 것. 스냅샷 게이트다 — 조용히 바뀌는
  것만 막는다. 의미의 정합은 여전히 사람이 본다
- **HTTP 메서드.** 경로만 잇고 메서드는 잇지 못한다
- **의미.** 이름이 맞아도 뜻이 다른 배선은 사람이 읽어야 한다
- **Apache 가 실제로 헤더를 내보내는가.** `.htaccess` 에 규칙이 있는 것과 적용되는 것은
  다르다. `AllowOverride None`·nginx 에서는 통째로 무시된다 — 배포 후 `curl -I` 가 계속 필요하다

### 티어 2 — 순수 단위 (`tier2_unit/`) · DB·서버 불필요 · 약 0.1초 · 53 케이스

| 파일 | 대상 |
|---|---|
| `t_10_cookie_header` | `build_set_cookie_header()` **86 케이스 불변식** (v1.1.0 의 71 케이스 복원·확장) |
| `t_20_perm_grades` | 3축 등급, 문자열 비교 금지, 만료 강등, `require_global_role` (D-50) |
| `t_30_validation` | `v_*` 경계값 · `page_params` clamp (D-154) · 시각 변환 · `enc/dec` · PKCE |
| `t_40_cookie_send` | `send_cookie()` 하한선과 fail-closed 3종 (D-65 · D-66 · D-75) |
| `t_50_opaque_shape` | `ck_opaque_shape_hint()` **자신을** 검증한다 (D-113). 티어 1 이 그 결과로 판정을 내므로, **일부만 놓치는 눈멂**을 여기서 잡는다 — 실제로 `array()` 긴 문법에서 키 0개를 내던 결함이 이 케이스로 잡혔다 |

**못 잡는 것**
- **실제로 나가는 헤더 바이트.** CLI SAPI 에서 `header()` 는 무동작, `headers_list()` 는
  빈 배열이다. 본체 `setcookie()` 와의 바이트 대조는 **티어 3** 이 한다
- **`bootstrap.php` 자신의 동작.** FORCE_HTTPS 301 · OPTIONS 204 · 예외 핸들러 · GC
- **상수 조합.** PHP 상수는 재정의가 불가능하다. 다른 `config.php` 세계를 보려면
  자식 프로세스가 필요하고, 실제로 한 케이스가 그렇게 한다 — 전수는 하지 않는다

### 티어 3 — 실측 (`tier3_live/`) · 실 MySQL/MariaDB + `php -S` · 약 11~15초 · 24 케이스

| 파일 | 대상 |
|---|---|
| `t_10_schema` | `schema.sql` **무수정** 적용 · InnoDB/utf8mb4 · `SUM(col = ?)` 관용구 · `result` 컬럼 폭 |
| `t_20_migration_paths` | **신규 설치 ↔ 업그레이드 두 경로**를 `information_schema` 로 직접 대조 (D-175) |
| `t_30_cookie_branches` | 두 분기 **바이트 동등성** 86 케이스 (v1.1.0 하네스 복원) |
| `t_40_blast_radius` | `api/**` 33파일 × GET+POST = **66 요청**의 봉투·누출·캐시 헤더 |
| `t_50_regression_walk` | register → login → me → 비밀번호 변경 → logout → **401** |
| `t_60_concurrency` | 동시 로그인 20건의 **신호 소실** · 멱등키 8건 동시 차감 |

**서버는 저장소 트리가 아니라 임시 샌드박스 복사본에 대고 뜬다.** `config.php` 도
거기에만 쓴다. 저장소에는 파일 하나 만들지 않는다.

**SQLite 스텁을 쓰지 않았다.** `schema.sql` 이 MySQL 전용(`ENGINE=InnoDB` ·
`ROW_FORMAT=DYNAMIC` · `utf8mb4_unicode_ci` · `BIGINT UNSIGNED`)이고 코드가
`SUM(status = ?)` 관용구에 의존한다. 두 번째 스키마는 드리프트를 만들고,
**그 드리프트가 정확히 이 프로젝트가 반복해 맞은 버그의 종류다.**

**못 잡는 것**
- **실 PHP 7.2 인터프리터.** 로컬에 없다. 7.2 분기는 버전 조건을 뒤집은 사본으로 강제
  실행한 것이다. 인터프리터 자체의 차이는 `php72_scan.php` 정적 검사로만 덮인다
- **`.htaccess` 재작성.** `php -S` 는 읽지 않으므로 물리 경로(`/server/api/auth/login.php`)로
  부른다. 계약의 확장자 없는 경로가 실제로 도달하는지는 **미검증**이다
- **진짜 병렬 처리.** `php -S` 는 요청을 직렬로 처리한다. 여기서 재현되는 것은
  "같은 순간에 도착한 여러 요청" 이지 "DB 트랜잭션이 겹치는 상황" 이 아니다.
  진짜 경합은 mod_php/FPM 배포에서만 난다
- **HTTPS 경로.** 샌드박스는 평문이다(`COOKIE_SECURE=false`). `secure` 속성이 붙는지는
  배포 후 개발자도구 확인 항목으로 남는다
- **v1.0.0~v1.2.0 에서 올라오는 업그레이드.** 기준선을 v1.3.0 하나로 잡았다.
  넓히려면 `mig_baseline_root()` 한 곳만 고치면 된다
- **브라우저·화면.** JS 는 실행되지 않는다

## 종료코드

`tools/` 의 규율을 그대로 확장한다 — **조치가 다르면 코드를 나눈다.**

| 코드 | 의미 | 무엇을 고쳐야 하나 | 재현 |
|---|---|---|---|
| `0` | 전부 통과. **그리고 실제로 1건 이상 실행됐다** | — | `--tier=2` |
| `1` | 실패 있음 | **산출물**(코드·문서) | 대상 코드에 결함이 있을 때 |
| `2` | 사용법 오류 / 대상 없음 | **명령·경로** | `--bogus` · `--tier=9` |
| `3` | **한 건도 실행되지 않았다** (전부 SKIP) | **환경** | DB 없이 `--tier=3` → `skip 24`. **DB 없이 `--tier=1,2,3`(기본)은 `0` 이다** — 티어 1·2 가 돌았으므로. 위 「DB 없이 돌린 `exit 0`」 참조 |
| `4` | **러너 자신이 고장이다** | **러너** | **양성 픽스처가 통과**했을 때 · **음성 대조군이 발화**했을 때 · 자기검증이 0건 실행됐을 때 · `selfcheck/` 가 없을 때 |

`0` · `2` · `3` 은 이 문서를 쓰면서 위 명령으로 다시 재현했다. `1` 은 스위트가 처음
돌던 날 실제로 났고(아래 「첫날 잡은 것」의 N-1), 그것이 닫히면서 `0` 이 됐다.

### `3` 과 `4` 가 왜 `0` 과 따로 있는가 — 이 프로젝트에서는 이것이 핵심이다

**「0건」이 「결함 없음」이 아니라 「검사기가 눈멀었음」이었던 적이 이 저장소에서만
누적 29번이다.** (v1.5.0 시점 집계 — 이전 라운드들이 세어 온 21건 + 이 라운드의
자기검증이 잡은 검사기 결함 6건 + **마감 점검이 잡은 2건**(아래 「마감 점검이 더 잡은
2건」). 세는 주체는 각 라운드의 리포트다.)

그중 여럿이 정확히 이 모양이었다.

| 실제로 겪은 것 | 무엇이 나왔나 | 진실 |
|---|---|---|
| `grep -c $'\r'` 로 CRLF 검사 | "전부 CRLF" | Git Bash 에서 **빈 패턴**이 되어 **총 행수**를 냈다. 10파일에 CRLF 를 써 넣을 뻔했다 |
| PHP `glob()` 로 파일 수집 | **0건** | 경로의 `[...]` 를 문자 클래스로 읽었다. 오류도 나지 않는다 |
| `sed` 로 프로브 함수 추출 | 파일이 만들어짐 | heredoc 안의 `}` 에서 잘려 **파스 에러**. 종료코드를 안 봤으면 "테스트가 도는데 결과가 없다" 로 오독 |
| `php -n tests/run.php` | **전부 통과** | `-n` 이 `mbstring`·`openssl` 을 껐다. 4 케이스가 조용히 빠졌다 |

**"통과" 와 "아무것도 안 돌았다" 가 같은 종료코드를 쓰면 회귀 게이트는 조용히 항상
통과한다.** 그것이 `3` 이 있는 이유다. 조치도 다르다 — `1` 은 코드를 고치라는 뜻이고
`3` 은 환경을 고치라는 뜻이다.

`4` 는 다른 것과 성질이 아예 다르다 — **본 실행을 하기 전에** 난다. 러너가 자기
검사기를 믿을 수 없는 상태에서 낸 "0건" 은 증거가 아니므로, **아예 판정을 내지 않는다.**
`1` 로 뭉개면 "고칠 코드"를 찾으러 가게 되는데 고칠 것은 러너다.

`--notes-are-errors` 는 `tools/php72_scan.php` 의 ERROR/NOTE 규율과 같다.
낡은 줄 번호 인용처럼 **동작은 안 깨지지만 사람을 틀린 자리로 보내는** 발견을 상시
실패로 만들면 게이트가 늘 빨갛게 되고, **늘 빨간 게이트는 없는 게이트다.**

## 러너 자신을 검증한다 (`selfcheck/`)

매 실행의 **0단계**다. `--no-selfcheck` 로 끌 수 있지만 CI 에서는 쓰지 마라.

| 파일 | 무엇을 하는가 |
|---|---|
| `s_10_positive.php` | 티어 1 검사기 11종을 **일부러 깨뜨린 미니 설치 루트**(`fixtures/positive/root/`)에 대고 돌린다. 잡아내야 정상 |
| `s_20_negative.php` | 같은 검사기를 **결함이 하나도 없는** 통제군(`fixtures/negative/root/`)에 돌린다. 조용해야 정상 |
| `s_30_cookie_oracle.php` | 쿠키 불변식 오라클에 **변이 7종**을 먹인다 — HttpOnly 누락 · SameSite 누락 · RFC 7231 날짜(D-68) · 이름 인코딩(V11-L-1) · 구분자 검사 제거 · 순서 뒤집기 · 빈 값 삭제. 전부 실제로 났거나 D-68 이 경고한 되돌림이다 |
| `s_40_live_oracle.php` | 스키마 비교기에 **어긋난 스키마 5종**을 먹인다 — 컬럼 삭제 · 타입 변경 · NULL 허용 변경 · 인덱스 삭제 · 테이블 삭제. DB 가 없으면 SKIP |

**양성 23 + 음성 16 = 39.** DB 없이 돌리면 `s_40`(양성 5 · 음성 2)이 빠져 **32** 가 된다.

요약 줄은 **양성과 음성을 나눠** 찍고, 빠진 픽스처를 이름까지 나열한다:

```
   positives 18/18 detected · negatives 14/14 silent · 7 fixture(s) SKIPPED (not self-verified)
   -- self-check SKIPS: these checkers were NOT verified in this run --
      x7  no test database configured (...)
            selfcheck/s_40_live_oracle.php :: the schema comparator sees a missing column
            ... (7건 전부)
```

> **왜 나눠 찍는가 — 라벨이 거짓말을 했다.**
> 이전 판은 `inv_detected / ran` 을 `n/m planted defects detected` 로 찍었다. 분모 `ran` 은
> **양성 + 음성 대조군의 합**이므로 실측 `18/32` 가 라벨대로는 **「결함 14개를 놓쳤다」**
> 로 읽혔다. 놓쳤다면 설계상 종료코드 `4` 인데 종료코드는 `0` 이었으니, 읽는 사람은
> 라벨과 종료코드 중 하나를 틀린 것으로 여기게 된다.
> **게이트 자체는 처음부터 옳았다** — 양성이 하나라도 통과하면 `fail++` 이고 러너가
> 그 자리에서 `4` 로 멈춘다(양·음 두 방향 모두 실측으로 재현했다). **틀린 것은 라벨뿐이었다.**
> 그리고 라벨이 틀리면 사람이 종료코드를 의심하게 되므로, 이 저장소가 반복해 고쳐 온
> **「0건을 결함 없음으로 읽는」 것과 같은 계열**의 결함이다.
>
> 같은 이유로 **자기검증의 SKIP 을 반드시 인쇄한다.** 러너는 본 실행 전에 `skips` 를
> 비우므로, 적어 두지 않으면 「무엇이 자기검증되지 않았는지」가 통째로 사라진다.
> `assert.php` 가 SKIP 마다 `phase` 를 달아 두는 이유가 그것이다.

**양성 픽스처가 하나라도 통과하면 종료코드 4 로 즉시 멈춘다.**
**음성 대조군이 하나라도 실패하면 그 검사기는 과검출이다** — 과검출하는 게이트는
며칠 안에 사람이 무시하게 되고, 무시되는 게이트는 없는 게이트다.

자기검증 파일이 아예 없어도 `4` 다. "검증되지 않은 0건" 을 통과로 인쇄하지 않는다.

### 음성 대조군이 실제로 값을 냈다

첫 실행에서 검사기 **6종의 결함**이 잡혔고 **그중 3건은 없는 결함을 지어내는 방향**이었다.

| 검사기 | 무엇이 틀렸나 | 방향 |
|---|---|---|
| `chk_page_links` | 상대 링크를 **스크립트 폴더** 기준으로 풀었다. `assets/api.js` 의 `login.html` 은 `public/login.html` 인데 `public/assets/login.html` 을 찾아 없다고 했다 | **지어냄** |
| `chk_phantom_identifiers` | 와일드카드 표기(`*_gte()`)와 메서드(`Object.keys()`)를 팬텀으로 신고 | **지어냄** |
| `h_files()` | `tests/fixtures/` 를 실제 코드와 함께 훑어 **자기 픽스처를 결함으로** 보고 | **지어냄** |
| `chk_table_constants` | 값 정규식이 `[a-z_]+` 라 대문자가 든 값을 놓쳤다 | 놓침 |
| `chk_migration_guards` | 양성 픽스처의 **주석 안**에 있던 `@skip-if` 문자열을 가드로 인식 | 놓침 |
| `cookie_check_invariants` | 71 케이스의 이름이 전부 인코딩 항등이라 **이름 인코딩 변이를 못 잡았다** | 놓침 |

통제군에는 **검사기를 속이기 쉬운 합법 패턴**을 모아 두었다 — 배열 리터럴의
trailing comma(함수 호출의 7.3+ 것과 `grep` 으로 구분 불가), 과거 릴리스를 가리키는
정당한 주석, 문자열 안의 `//`, 주석 안의 `href=`. 이것이 없었으면 위 3건이 결함
리포트에 실렸을 것이다.

### 마감 점검이 더 잡은 2건

위 6건은 **첫 실행**에서 음성 대조군이 잡은 것이다. 라운드 마감 점검에서 2건이 더 나왔다.
둘 다 **재현을 먼저 만들고** 고쳤다.

| 검사기 | 무엇이 틀렸나 | 방향 |
|---|---|---|
| `chk_table_constants` | `CREATE TABLE` 정규식이 **줄머리에 고정되지 않아** 주석 속에서 *인용된* `CREATE TABLE` 문자열을 정의로 셌다 | **양쪽** |
| `ck_opaque_shape_hint` | `array(` 긴 문법에서 **키 0개**를 냈다. 짧은 문법 `[`만 동작했다 | 놓침 |

`chk_table_constants` 는 같은 함수의 **두 번째** 결함이다(위 표의 "값 정규식 `[a-z_]+`"
와 별개). 이번 것은 두 방향 모두 재현됐다:

- **거짓 양성** — `schema.sql` 머리에 ``--   CREATE TABLE IF NOT EXISTS `app_ulogin_ghost` (``
  주석을 넣으면 정본 0건이 1건이 된다. 정의 계수도 17 → 18
- **거짓 음성(게이트가 죽는 방향)** — `app_ulogin_terms` DDL 을 통째로 지우면 게이트가
  옳게 1건을 낸다. 그런데 머리 주석이 그 이름을 인용해 두면 **0건으로 조용해진다.**
  실제 드리프트를 두고 「깨끗함」을 보고하는 것이므로 게이트로서 가장 나쁜 오류다

**같은 결함이 `server/migrations/lib.php` 의 파서 3곳에도 있었고 같은 라운드에서
고쳤다.** 같은 `schema.sql` 을 읽는 파서가 넷인데 그중 하나만 규약이 달랐던 것이다 —
고정한 뒤 넷이 같은 규약을 쓴다. **대가도 같다: 들여쓴 `CREATE TABLE` 은 보이지 않는다**
(정본 schema.sql 의 정의 17개는 전부 줄머리에 있다. 들여쓴 정의 0건, 실측).

`ck_opaque_shape_hint` 는 이 마감 점검이 **새로 만든** 검사기이고, **그것을 검증하려고
같이 만든 티어 2 케이스가 곧바로 결함을 잡았다.** 검사기를 먼저 검증한다는 규율(D-113)이
새 코드에서 값을 낸 자리다 — 그 케이스가 없었으면 티어 1 의 못박기가 「키 0개 = 바뀐 것
없음」으로 통과했을 것이다. 그래서 호출부에 `0건 → fail` 가드도 함께 넣었다.

### 복원한 하네스를 그대로 믿지 않았다 — 쿠키 71 → 86

v1.1.0 의 71 케이스를 그대로 옮기는 것이 이 라운드의 원래 계획이었다.
옮긴 뒤 **변이를 심어 봤더니 오라클이 못 잡았다.**

심은 변이는 감사 `V11-L-1` 의 실제 사고다 — 쿠키 **이름**이 URL 인코딩되어
`ulogin[sid]` 가 7.2 에서만 `ulogin%5Bsid%5D` 로 나가고 로그인이 조용히 깨진 것.
못 잡은 이유는 단순했다: **71 케이스의 이름이 전부 `ULOGIN_SID` 류라
`rawurlencode` 가 항등이었다.**

`ulogin[sid]` · `ulogin+sid` · `ulogin/sid` 류의 이름을 넣어 그 변이를 잡게 만들었다.
**71 을 그대로 저장했다면 "복원했다" 고 적으면서 실제로는 그 사고를 못 잡는
하네스를 남겼을 것이다.**

지금의 구성은 `cookie_cases()` 를 직접 실행해 셀 수 있다.

```bash
php -r "require 'tests/lib/cookie_oracle.php'; \$c=cookie_cases(); echo count(\$c);"
# 86  — 정상 경로 48(A) + 거부되어야 하는 입력 28(I) + D-75 계열 10(D)
#        그중 10 케이스는 이름이 rawurlencode 항등이 아니다 = 위 변이를 잡는 자리
```

## 부산물

**남기지 않는다. 실패해도, 예외로 죽어도.** `register_shutdown_function` 으로 건다.

| 만드는 것 | 어떻게 되돌리는가 |
|---|---|
| 테스트 DB (`ulogin_test*`) | `DROP DATABASE`. 이름이 `ulogin_test` 로 시작하지 않으면 **만들지도 지우지도 않는다** |
| 임시 샌드박스 웹루트 | 재귀 삭제. 못 지우면 **경로를 찍어 경고한다**(안에 `config.php` 가 있다) |
| `php -S` 프로세스 | Windows 는 `taskkill /T` 로 **트리째**. `proc_terminate` 만으로는 `cmd.exe` 래퍼만 죽고 서버가 살아남아 다음 실행이 **남의 서버에 붙는다** |
| `error_log` 임시 파일 | 종료 시 삭제. 줄 수만 요약에 인쇄한다 (fail-closed 경로가 일부러 남기는 로그다) |
| 자식 프로세스용 임시 파일 | `finally` 로 삭제 |

서버가 뜬 뒤에는 **센티널 파일**로 "지금 응답하는 것이 이번 실행의 샌드박스인가" 를
확인한다. 좀비 서버가 포트를 쥐고 있으면 readiness 검사는 통과하지만 요청은
**다른 문서 루트**로 간다 — 통과하든 실패하든 이번 코드에 대한 판정이 아니게 된다.

## 릴리스 절차에서의 자리

`tools/README.md` 의 릴리스 순서에서 **1·2단계를 이 스위트가 대신 돌린다**
(`php72_scan` · `bump_asset_version --dry-run` 을 티어 1 이 위임 실행한다).

```bash
php tests/run.php                     # 종료코드 0 을 확인한다. 3 은 통과가 아니다
php tools/bump_asset_version.php <새버전> --version-txt=<새버전>_<YYYYMMDD>
# 업로드 (server/ public/ examples/ 만) -> server/migrate.php -> INSTALL.md 8절 확인
```

**`--tier=1` 만 돌려 종료코드 0 을 얻고 넘어가지 마라.** 그 실행은 티어 2·3 을
아예 세지 않으므로 `0` 이 나온다. 요약 줄의 `executed` 값을 함께 보라.

## 새 테스트를 추가할 때

1. **`glob()` 을 쓰지 마라.** 이 저장소가 놓이는 경로에 대괄호가 들어가는 사례가 있고
   (`.../[일반] .../`), `glob()` 은 그것을 문자 클래스로 읽어 **오류 없이 0건을 반환한다.**
   `tests/lib/harness.php` 의 `h_files()` 를 써라 (`scandir()` + 수동 필터)
2. **PHP 7.2 문법만.** `php tests/run.php --tier=1` 이 `tests/` 자신도 스캔한다
3. **줄 번호를 단언에 넣지 마라** (D-92). 파일명 + 함수명으로 가리켜라
4. **자기 참조 단언 금지** (D-73). 현재 출력을 골든으로 얼리지 마라 —
   그러면 "코드가 코드대로 동작한다" 만 말한다. 계약·규격에서 **독립적으로** 유도한
   불변식을 적어라. `lib/cookie_oracle.php` 가 그 방식의 본보기다
5. **검사기를 먼저 검증하라.** 새 검사기에는 `selfcheck/` 에 양성·음성 픽스처를 함께 넣어라.
   검증되지 않은 "0건" 은 증거가 아니다
6. **"0건"과 "수집기가 눈멀었다"를 구분하라.** 대부분의 검사에 인벤토리 하한 케이스가
   따로 붙어 있는 이유다 (`... is not blind`)
7. **부산물을 정리하라.** 실패 경로에서도 지워지게 `finally` 나 shutdown 훅을 써라
8. **대상 코드를 고쳐서 테스트를 통과시키지 마라.** 반대도 마찬가지다 —
   이 라운드에 실제로 있었던 일이다. `t_10_schema` 의 테이블 계수기가 `schema.sql`
   **주석 안의** `CREATE TABLE` 문자열까지 세는 것을 백엔드 담당이 발견했고,
   **테스트를 고치는 대신 자기 주석의 표현을 바꿨다.** 대상을 고치려고 테스트를
   고치기 시작하면 안전망이 무너진다
